# InternetMap-Geographic 超大规模纯拓扑压力测试

## 测试目的

本示例使用 `docker-compose-10k-with-geo.yml` 验证上传模式下(upload)超大规模静态拓扑的解析、布局和渲染能力，并检查拓扑加载完成后的地图、右下角面板、Tab 和设置按钮是否能够持续响应。

这是纯拓扑压力测试，不要求构建或启动 YAML 中的容器，也不产生网络流量。发包、录制、回放和蠕虫增长压力应使用其他示例单独测试，避免流量处理影响纯拓扑结果。

当前测试文件的输入规模如下：

| 项目 | 数量 |
| --- | ---: |
| 文件大小 | 约 15.4 MiB |
| Compose services | 9,957 |
| Compose networks | 9,343 |
| service-network 挂载关系 | 27,097 |
| 页面当前预期 | 约 19,298 nodes / 27,097 links |

页面数量取决于解析和节点映射规则。规则发生调整时，应先解释差异，再更新本表和自动化断言。

当前测试环境：

| 项目 | 配置 |
| --- | --- |

| 虚拟机可用 CPU | 4 个在线逻辑 CPU（0–3） |

## 2. 启动可视化

使用仓库 Docker Compose 部署时，在仓库根目录执行：

```bash
docker compose up -d --build seedemu_internet_map_geographic
```

也可以在 `InternetMap-Geographic/frontend` 下启动前端开发服务：

```bash
pnpm install
pnpm dev
```

根据部署方式访问上传页面：

| 模式 | Docker 部署 | 前端开发服务 |
| --- | --- | --- |
| 3D | `http://<ip>:8090/pro/upload/3d` | `http://localhost:5174/dev/upload/3d` |
| 2D | `http://<ip>:8090/pro/upload/2d` | `http://localhost:5174/dev/upload/2d` |

`<ip>` 为运行可视化服务的主机地址。

## 3. 冷加载测试

1. 新建浏览器标签页并打开 3D 上传页面。
2. 可选：打开开发者工具 Performance 和 Memory 面板。开发者工具会增加额外开销，开启和关闭时的结果应分开记录。
3. 选择本目录的 `docker-compose-10k-with-geo.yml`。
4. 点击 **Parse file**，同时开始计时。
5. 等待加载遮罩消失，地球、节点、连线和右下角面板全部出现后停止计时。
6. 核对 Overview 显示的节点和连线数量，观察是否有解析错误、空白画面或浏览器崩溃。
7. 保持页面不操作 30 秒，记录稳定后的内存占用以及 CPU/GPU 是否持续异常占用。
8. 关闭该标签页并重新打开，重复 3 次；首次结果和后两次结果分别记录。
9. 在 2D 上传页面重复以上步骤。

至少记录以下时间点：

- 点击 Parse file 到加载遮罩出现；
- YAML 解析完成；
- 节点和连线首次可见；
- 加载遮罩消失、页面可操作。

只记录总耗时也可以用于基础比较，但不能区分 YAML 解析、图布局和 Cesium 首帧渲染各自的成本。

## 4. 地图交互压力

加载完成并静置 10 秒后，按固定顺序操作，每项持续约 10 秒：

| 编号 | 操作 | 观察内容 | 通过标准 |
| --- | --- | --- | --- |
| T01 | 连续拖动并旋转 3D 地球 | 拖动是否跟手、连线是否持续显示 | 不冻结、不崩溃；松手后能立即继续操作 |
| T02 | 连续放大和缩小 | 帧率、图标和连线清晰度 | 图形没有明显变糊、丢失或错位 |
| T03 | 连续点击不同节点 | 点击响应、选中高亮和详情 | 选中目标正确，不出现长时间无响应 |
| T04 | 开启 Hover details 后移动鼠标 | 悬停卡片和鼠标移动响应 | 卡片对应目标节点，关闭后额外拾取开销消失 |
| T05 | 搜索一个已知节点并清空 | 输入、建议列表、高亮和定位 | 输入不中断，结果正确，清空后恢复 |

建议使用浏览器 Performance 面板记录每项操作，关注主线程 Long Task、交互延迟、帧间隔和 GPU 活动。肉眼感受也需要记录，但不应只写“流畅”或“卡顿”，应同时注明触发操作和最长停顿时间。

## 5. 右下角面板与按钮压力

地图数据加载完成后执行，避免把首帧构建时间计入 Tab 响应：

1. 按 `Overview → Settings → Traffic Replay → Overview` 顺序连续切换 10 轮。
2. 每次确认 Tab 的激活样式和对应内容已经更新。
3. 连续执行面板最小化和展开 10 次。
4. 在 Overview 中打开、关闭 AS 和 IX 选择器；选择一个项目后清空。
5. 在 Settings 中依次取消并恢复 Host、Router、Network、IX。
6. 核对隐藏类型时关联连线同步隐藏，恢复后节点和连线重新出现。
7. 调整 Node / link scale，分别移动到最小值、中间值和最大值。
8. 开关 Node labels 和 Hover details。
9. 在执行上述面板操作的同时拖动或缩放地图，再重复一轮。

类型可见性开关采用已有图元分组的 `show` 切换。取消或恢复勾选不应重新解析 YAML、重新计算曲线或清空完整拓扑。若开关后出现长时间停顿，应记录具体类型、当前 Tab 和停顿时间。

通过标准：

- 所有点击最终只触发一次对应状态变化，不丢点击、不重复切换；
- Tab、复选框、滑块、选择器和最小化按钮均保持可用；
- 操作期间页面不崩溃、不白屏，不出现持续增长且无法回落的任务积压；
- 面板内容和下边缘不被其他浮层遮挡；
- 地图静止时切换 Tab 不应重建拓扑几何；
- 隐藏后恢复的节点和连线数量与操作前一致。
